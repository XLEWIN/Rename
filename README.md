## DEPLOY TO RAILWAY

Everything Railway needs is already in the repo:

| File | Purpose |
|------|---------|
| `railway.json` | Pins the builder to the Dockerfile, sets the `/health` health-check and `ON_FAILURE` restart policy |
| `Dockerfile` | Multi-stage build — **installs every package in `requirements.txt` at build time**, plus `ffmpeg` |
| `.dockerignore` | Keeps `.env`, `*.session`, `logs/` and `__pycache__` out of the image |
| `.env.example` | Full list of every environment variable the bot reads |
| `Procfile` | `web: python bot.py` (Nixpacks / Heroku style fallback) |

### 1. Push the code

Push this folder (`Dockerfile`, `bot.py`, `requirements.txt`, ...) as a GitHub
repo. If the repo has extra parent folders, set **Root Directory** in Railway to
the folder that contains the `Dockerfile`.

### 2. Create the service

1. https://railway.app -> **New Project** -> **Deploy from GitHub repo**
2. Railway picks up `railway.json` -> builder `DOCKERFILE`
3. On every deploy Railway runs `pip install -r requirements.txt` inside the
   build stage, so **no package has to be installed by hand**, and `ffmpeg`
   comes from the runtime `apt-get` layer.

### 3. Set the variables

Railway -> your service -> **Variables** -> copy from `.env.example`:

**Required for your own bot**

| Variable | Notes |
|----------|-------|
| `API_ID` / `API_HASH` | from https://my.telegram.org |
| `BOT_TOKENS` | from `@BotFather` (space-separate several bots) |
| `OWNER_ID` | your numeric Telegram user id |
| `DB_URL` / `DB_NAME` | MongoDB connection string |
| `LOG_CHANNEL` / `DUMP_CHANNEL` | bot must be admin, use `-100...` ids |

**Optional:** `GROQ_API_KEY`, `TMDB_API_KEY`, `FANART_API_KEY`,
`USER_SESSION_STRING` (4 GB uploads), start/force/about pictures, bot identity
links and every tuning knob — see `.env.example` for each key and its default.

Leave `PORT` alone: Railway injects it and the bot binds `0.0.0.0:$PORT`
automatically (local fallback is `8023`). Empty variables are treated as
"not set" instead of crashing the process.

### 4. Health-check

The bot also runs a small aiohttp server exposing `/health`, `/ping`,
`/metrics` and `/stats` on the Railway port. A deploy goes healthy once
Telegram connects; failed services restart automatically (max 10 retries).
